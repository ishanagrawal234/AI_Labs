TASK 1 -- Understand the Problem Before Coding
==============================================

1. Mathematical Specification of the Problem:
   - Input Space X: X = {0, 1}^2 (the set of all pairs of redundant binary sensor readings)
   - Output Space Y: Y = {0, 1} (binary sensor-disagreement warning indicator)
   - Four Labelled Examples:
       (x1 = 0, x2 = 0) -> y = 0  (both sensors inactive; agreement)
       (x1 = 0, x2 = 1) -> y = 1  (sensor 2 active, sensor 1 inactive; disagreement warning)
       (x1 = 1, x2 = 0) -> y = 1  (sensor 1 active, sensor 2 inactive; disagreement warning)
       (x1 = 1, x2 = 1) -> y = 0  (both sensors active; agreement)

2. Geometric Sketch of the Four Points in the (x1, x2) Plane:

      x2 ^
         |
     1.0 +    (0, 1) [Class 1]             (1, 1) [Class 0]
         |         o                            x
         |
         |
         |
     0.0 +    (0, 0) [Class 0]             (1, 0) [Class 1]
         |         x                            o
         +---------+----------------------------+---------->
                  0.0                          1.0       x1

     Legend:
       'o' = Class 1 (Disagreement warning active)
       'x' = Class 0 (No warning; agreement)

3. Why One Straight Decision Boundary Cannot Separate the Two Classes:
   A single linear decision boundary in R^2 is defined by the hyperplane
   w1 * x1 + w2 * x2 + b = 0, which divides the plane into two open half-spaces:
   w^T x + b > 0 and w^T x + b < 0. In the XOR configuration, the two positive
   examples (0, 1) and (1, 0) lie on one diagonal line segment, while the two
   negative examples (0, 0) and (1, 1) lie on the opposing diagonal line segment.
   These two line segments intersect at the point (0.5, 0.5). By Radon's Theorem
   and the convex hull property, two sets cannot be linearly separated if their
   convex hulls intersect. Any single straight line that groups (0, 1) and (1, 0)
   on one side will inevitably include either (0, 0) or (1, 1).

4. Prediction for a Single Affine Transformation with Sigmoid Output:
   A model of the form y_hat = sigma(w1 * x1 + w2 * x2 + b) can only form a single
   straight decision boundary. It cannot represent the XOR function. When trained
   with gradient descent, the weights will either collapse toward zero (predicting
   the base rate p = 0.5 for all inputs) or fit at most three out of the four points,
   yielding an accuracy capped at 75% (or 50%) and a binary cross-entropy loss that
   stagnates near -ln(0.5) approx 0.69315.

Checkpoint 1 -- Problem Specification & Linear Prediction:
- Task: XOR sensor disagreement detection on {0, 1}^2.
- Linear prediction: Stagnates at loss approx 0.693, cannot achieve 100% accuracy.
  (Confirmed experimentally in Task 1: final BCE loss was 0.69315, accuracy was 3/4).

Think About It:
"A model can have many parameters and still have the wrong kind of representation.
What scientific claim about representation does XOR let us test with only four data points?"
XOR scientifically demonstrates that depth alone without nonlinearity does not increase
representational capacity. A stack of any number of affine layers (e.g. W3 * (W2 * (W1 * x + b1) + b2) + b3)
mathematically collapses to a single affine transformation W_net * x + b_net. Even with
hundreds of parameters, an affine-only network cannot represent XOR. With just four data
points, XOR proves that nonlinear activation functions are strictly necessary to expand
the hypothesis space from linear half-spaces to nonlinear decision regions.



TASK 2 -- Design the Intelligent Agent
======================================

Baseline Architecture:
   2 Inputs (x1, x2) ---> 2 Hidden Units (h1, h2) ---> 1 Output Logit (z) ---> Sigmoid (p)

Engineering Design Choices:
- Hidden Layer Activation: Nonlinear activation f(a). Initially Sigmoid or Tanh; later ReLU.
- Output Layer: Single linear unit producing logit z, transformed via sigmoid into probability p in (0, 1).
- Loss Function: Binary Cross-Entropy (BCE) with logits:
    L(z, y) = max(z, 0) - z * y + ln(1 + exp(-|z|))
- Optimiser: Gradient-based optimisation (Adam with learning rate 0.05 - 0.1, or SGD with momentum).

Questions:
1. Why is the hidden nonlinearity scientifically necessary here?
   If the hidden layer were linear (f(a) = a), the composite function from inputs x to
   output logit z would be:
       z = W^(2) * (W^(1) * x + b^(1)) + b^(2) = (W^(2) * W^(1)) * x + (W^(2) * b^(1) + b^(2))
   which is identical to a single affine transformation W_eff * x + b_eff.
   A nonlinear activation f(a) warps the geometry of the input space. It projects the
   four non-linearly separable points in R^2 into a 2D hidden activation space h = (h1, h2)
   where the positive and negative points become linearly separable by the second layer.

2. Why is sigmoid plus binary cross-entropy a sensible engineering pairing for the output?
   1) Probability semantics: Sigmoid maps any real-valued logit z in (-inf, +inf) smoothly
      into the valid probability interval (0, 1).
   2) Gradient well-behavedness: Under Mean Squared Error (MSE), the derivative contains
      the term sigma'(z) = sigma(z) * (1 - sigma(z)). If the model makes a confident wrong
      prediction (|z| >> 0), sigma'(z) -> 0, causing the gradient to vanish and freezing
      learning. Under Binary Cross-Entropy, the derivative with respect to logit z is:
          dL/dz = sigma(z) - y = p - y
      The sigmoid derivative cancels out completely, leaving an error signal directly
      proportional to the prediction error (p - y). When the network is wrong, the gradient
      is large and corrective.
   3) Numerical stability: Implementing this pairing via `nn.BCEWithLogitsLoss` combines
      the sigmoid and log-loss operations using the log-sum-exp formulation, preventing
      numerical underflow or overflow when |z| is large.

3. What evidence will count as successful learning?
   Three concrete validation criteria:
   1) Final Loss Criterion: The BCE loss must drop from approx 0.693 down to L < 0.01.
   2) Prediction Accuracy Criterion: Thresholding predicted probabilities at 0.5 must yield
      all four labels correct (4/4, 100% accuracy), with p < 0.05 for (0,0) and (1,1),
      and p > 0.95 for (0,1) and (1,0).
   3) Nonzero Gradient & Learning Signal: Early weight gradients dL/dW^(1) must be nonzero,
      and parameter trajectories across epochs must show steady, directed convergence away
      from initial random weights toward distinct feature detectors.

Think About It:
"The hidden units are not given target values. If the network learns XOR, what has
determined what each hidden unit should compute? Relate your answer to the role of
backpropagation."
The hidden units have no direct supervision. What they compute is determined entirely by
the chain rule of calculus via backpropagation. Backpropagation takes the scalar error
at the output (p - y) and distributes it backward to each hidden unit j via:
    delta_j^(1) = (W_j^(2) * (p - y)) * f'(a_j^(1))
This derivative quantifies how much unit j contributed to the output error. Gradient
descent updates W^(1) in the direction that reduces this error, forcing the two hidden
units to specialize into complementary intermediate features--typically, one hidden unit
learns an "OR" boundary (active if x1 or x2 is 1) and the other learns an "AND" boundary
(active only if both x1 and x2 are 1). The output unit then computes OR minus AND,
solving XOR.

       dL / dW^(1) = (1 / N) * sum_{k=1}^N (d l_k / dW^(1))

5      | 0.69315    | True             | R0: [0.0000, 0.0000], R1: [0.0000, 0.0000]
--------------------------------------------------------------------------------

Mathematical Explanation of Symmetry Trapping:
For any input x, the pre-activations are a_1^(1) = W_(0,:)^(1) x + b_1 = 0 and
a_2^(1) = W_(1,:)^(1) x + b_2 = 0. Thus, h_1 = f(0) and h_2 = f(0) are identical.
In the backward pass, the incoming error signals to the hidden units are:
    delta_1^(1) = W_1^(2) * delta^(2) * f'(a_1^(1))
    delta_2^(1) = W_2^(2) * delta^(2) * f'(a_2^(1))
Since W_1^(2) = W_2^(2) = 0 and a_1 = a_2, delta_1^(1) = delta_2^(1).
Consequently, the gradients for both rows are identical:
    dL / dW_(0, j)^(1) = dL / dW_(1, j)^(1)
Because both rows start at identical values and receive identical updates at every step,
they remain permanently identical for all future iterations. The network is trapped in a
symmetric subspace: it cannot learn distinct feature detectors and effectively behaves
as a 2-1-1 network, permanently failing to solve XOR. Random weight initialisation is
essential to break this symmetry.

Interpretation Paragraph:
All three activations successfully learned the XOR mapping given appropriate learning rates
and random seeds. However, their internal dynamics differ noticeably. Sigmoid outputs are
strictly positive in (0, 1), which introduces non-zero-centered hidden representations
that can slow down gradient convergence. Tanh is symmetric and zero-centered in (-1, 1),
allowing hidden states to balance positive and negative activations and yielding faster
loss reduction (0.000082 vs 0.000223). ReLU achieved the lowest final loss (0.000037)
because its gradient is exactly 1 for positive pre-activations, eliminating vanishing
gradient issues in the active regime. However, in small architectures like 2-2-1, ReLU carries
the engineering risk of "dead units" if pre-activations become negative for all inputs,
highlighting the tradeoff between gradient flow and robustness in tiny models.

Think About It:
"If a sigmoid unit is saturated, its derivative is close to zero. If a ReLU unit is
negative, its derivative is zero. These are different mechanisms that can both produce
a small gradient. How would you distinguish them by inspecting activations and pre-activations?"
To diagnose the cause of a vanishing gradient:
1. Saturated Sigmoid: Inspect pre-activation a and activation h = sigma(a). If |a| >> 0
   (e.g., a > 5 or a < -5), the activation h is near 1.0 or 0.0. The derivative
   sigma'(a) = h * (1 - h) is smoothly approaching zero from the positive side (e.g. 1e-4).
   The unit is saturated in its flat asymptotic tails.
2. Dead ReLU: Inspect pre-activation a and activation h = max(0, a). If a < 0 for ALL
   training examples, the activation h is exactly 0.0, and the subgradient is identically
   zero (0.0). Unlike sigmoid, ReLU's derivative does not approach zero smoothly; it drops
   discontinuously to zero and stays zero across the entire negative domain. Checking
   `torch.all(pre_activations <= 0)` immediately identifies a dead ReLU unit.

Predictions Prior to Code Acceptance:
1. Shape of Final Weight Matrix: The second-layer weight matrix `fc2.weight` must have
   shape [3, 2] (3 output classes as rows, 2 hidden unit activations as columns).
2. Number of Logits per Example: Exactly 3 logits (one unnormalised log-odds score per class).
3. Why Softmax Probabilities Sum to One:
   Softmax is defined as p_i = exp(z_i) / sum_{j=1}^K exp(z_j). Summing over all classes i:
       sum_{i=1}^K p_i = sum_{i=1}^K (exp(z_i) / sum_{j=1}^K exp(z_j))
                       = (sum_{i=1}^K exp(z_i)) / (sum_{j=1}^K exp(z_j)) = 1.
4. Why the Logit Gradient Has the Form (p - y):
   For cross-entropy loss L = -sum_{k} y_k ln(p_k) where y is a one-hot target vector:
       dL / dz_i = sum_k (dL / dp_k) * (dp_k / dz_i)
   Using the Jacobian of softmax dp_k / dz_i = p_i (delta_{ik} - p_k):
       dL / dz_i = - (y_i / p_i) * p_i * (1 - p_i) - sum_{k != i} (y_k / p_k) * (-p_k * p_i)
                 = - y_i (1 - p_i) + sum_{k != i} y_k p_i
                 = p_i * sum_k y_k - y_i
   Since y is one-hot (sum_k y_k = 1), this simplifies directly to:
       dL / dz_i = p_i - y_i  (Vector form: nabla_z L = p - y).

Numerical Stability Diagnostic (Shift Invariance):
When a constant C = 100 was added to all logits (z_new = z + 100), the maximum absolute
difference between original and shifted probabilities was 4.07e-10 (identical within
floating-point roundoff).
Reason:
   p_i_new = exp(z_i + C) / sum_j exp(z_j + C)
           = (exp(z_i) * exp(C)) / (sum_j exp(z_j) * exp(C))
           = exp(z_i) / sum_j exp(z_j) = p_i.
Why frameworks subtract max(z): In standard 32-bit floats, exp(z) overflows to +inf
for z > 88.7. To prevent floating-point overflow, numerically stable implementations
subtract max_k(z_k) from all logits before exponentiating, keeping the maximum exponent at 0.

SECTION 6 -- Reflection Questions
=================================

1. What did the XOR experiment demonstrate about the difference between depth and nonlinearity?
The XOR experiment demonstrates that depth without nonlinearity provides no representational
advantage. A composition of affine transformations collapses into a single affine transformation,
meaning that an arbitrarily deep linear network cannot separate XOR. Nonlinearity, however,
bends and folds the coordinate space, enabling intermediate layers to map linearly inseparable
inputs into a space where a hyperplane can separate them. Thus, nonlinearity is the true source
of geometric expressiveness in deep neural models; depth provides hierarchical abstraction,
but only when interleaved with nonlinear activations.

2. In your successful run, what evidence showed that backpropagation supplied a useful learning signal rather than merely a nonzero gradient?
The primary evidence is that parameter updates caused systematic, monotonic descent on the
loss surface (from initial loss 0.698 down to 0.0005) rather than random diffusion. Furthermore,
the gradient vector nabla_W^(1) L drove the two hidden units to differentiate into distinct,
complementary feature detectors (one detecting OR and one detecting AND), as shown by the
weights breaking symmetry and arriving at high-confidence classifications (>99.9% probability)
on all four inputs. A merely nonzero gradient could wander aimlessly or oscillate; backpropagation
specifically supplied the direction of steepest descent toward the global solution.

3. Why did identical/zero weight initialisation prevent the two hidden units from learning distinct features?
Because identical initial weights cause both hidden units to compute identical pre-activations
and activations for every input (h1 = h2). When backpropagating, the output error passes through
identical outgoing weights, causing both hidden units to receive identical gradient updates
(dL/dW_(0,:)^(1) = dL/dW_(1,:)^(1)). Since their starting values and updates are identical,
they remain identical at every step. This symmetry trap prevents the units from specializing,
effectively reducing the hidden layer to a single unit, which mathematically cannot solve XOR.

4. How did changing the hidden activation affect the gradient you observed? Distinguish the scientific explanation from the engineering observation.
- Engineering Observation: The measured early gradient norm ||nabla_W^(1) L||_2 was 0.005453
  for Sigmoid, 0.005077 for Tanh, and 0.004868 for ReLU. During subsequent training, ReLU and
  Tanh converged in fewer epochs and achieved lower final loss (3.7e-5 and 8.2e-5) than Sigmoid (2.2e-4).
- Scientific Explanation: Sigmoid outputs are non-zero-centered in (0, 1), which constrains
  all weight gradients entering a neuron to have the same sign as the output error, forcing
  suboptimal zig-zag optimization trajectories. Tanh is zero-centered in (-1, 1), which facilitates
  balanced gradient updates. ReLU has a constant derivative of 1 for active units, preventing
  gradient attenuation regardless of depth, though in small models it risks permanent unit death
  if pre-activations fall below zero.

5. Why must the output layer and loss be selected together according to the task?
The output activation and loss function must be matched so that their mathematical pairing
produces an uncorrupted, well-conditioned error gradient. For binary classification, pairing
a sigmoid output with Binary Cross-Entropy results in the gradient dL/dz = p - y, directly
scaling with the prediction error. If one mistakenly paired sigmoid with Mean Squared Error (MSE),
the gradient would include the term p(1 - p), which vanishes when the model is confidently wrong,
stalling learning. Similarly, multi-class classification requires softmax paired with categorical
cross-entropy to produce the clean logit gradient p - y. Matching output activations with their
corresponding canonical link loss functions ensures proper probabilistic interpretations and
avoids vanishing or exploding gradients.

6. Give one example where the LLM improved your engineering productivity and one example where human verification was essential.
- Productivity Improvement: The LLM instantly generated the complete PyTorch training harness,
  including parameter initialization, training loops, tensor slicing, and evaluation metrics,
  saving considerable development time compared to writing boilerplate code from scratch.
- Essential Human Verification: Human verification was essential in identifying that the LLM's
  initial recommendation of separate `torch.sigmoid()` followed by `nn.BCELoss()` was numerically
  suboptimal, and replacing it with `nn.BCEWithLogitsLoss()`. Human understanding was also necessary
  to verify that the zero-initialization experiment failed specifically due to symmetry trapping
  rather than a bug in the gradient calculation.

7. Which tests in this laboratory would you keep if the model were scaled up, and which would become too expensive?
- Tests to Keep at Scale:
  1) Tracking loss trajectories and validation accuracy across epochs.
  2) Monitoring gradient norms (e.g. ||nabla_W L||) to detect vanishing/exploding gradients.
  3) Softmax probability sum-to-1 sanity checks and shift-invariance diagnostics.
- Tests Too Expensive at Scale:
  1) Computing and comparing example-wise gradients manually (requires N separate backward passes,
     prohibitive for large datasets and batch sizes).
  2) Full parameter matrix inspection and exhaustive finite-difference gradient checks
     (untenable for models with billions of parameters).
